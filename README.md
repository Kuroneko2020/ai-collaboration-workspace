# AI 协作区建立与优化

**一个独立的研发项目：结合用户的实践经验与喜好，标准化建设可分发的空白 AI 工作区。**

公开仓库：[Kuroneko2020/ai-collaboration-workspace](https://github.com/Kuroneko2020/ai-collaboration-workspace)。

> 当前源码版本为 `0.1.0-preview.6`：保留普通自动记忆与精简根目录，分发模板不预设 AI 人格或灵魂模块；维护指南含通用迁移/改名流程与大工作区检索纪律；发行包内置升级脚本，旧工作区由 AI 按包内规程一键升级。请按下方步骤从源码生成干净包，再选择解压后的 `个人AI协作区` 作为独立实际工作区，不要在研发项目根或模板源码中初始化。此仓库提供预览版源码与测试，尚未提供 GitHub Release。

## 这个项目要解决什么

个人 AI 工作中心不只是一个代码目录。它可以承载开发、工作、学习和生活事务，让资料、成果与记录围绕实际事情组织，并通过有来源、可纠正的协作记忆减少反复说明。

本项目结合用户在当前工作区中的实践经验与喜好，逐步提炼并标准化为可分发的空白工作区，使其他人能够从干净文件夹开始，按自己的情况建立组织方式，并在各自授权范围内形成偏好与记忆。分发模板不携带作者的个人偏好或 AI 人格设定。

`AI协作区建立与优化` 是独立研发项目；研发、测试和分发模板本身不会修改或替换用户当前工作区。若要将某项成果应用到当前工作区，须作为另一项明确的工作单独处理。

## 三部分的关系

- **实际工作区**：日常使用的位置，也是本项目在用户授权范围内提炼实践方法的来源；它的现行状态始终由自身权威文件维护，本项目不替代或自动修改它。
- **本项目**：独立进行方法研究、标准化设计、模板与工具研发、隔离验证及建设记录。
- **可分享成果**：经过明确筛选和验证的通用内容，不包含作者的个人资料、个人记忆、AI 人格设定或私人配置。

模板研发以用户的真实实践为输入，记录通用方法的变化、适用范围与验证；对实际工作区的任何改动或成果应用都属于另一个独立任务。项目不是一次性压缩任务，也不集中收集所有日常任务的流水账。

## 从源码生成并使用模板

需要已安装 Python 3.11+。Windows 可下载本仓库 ZIP 并解压，或克隆到本地；在包含本 README 的研发项目根目录运行：

```powershell
py -3 -B -X utf8 工具/打包.py --json
```

构建器会检查干净模板并在本地新建 `发行/`，生成候选 ZIP 和 `.zip.sha256`。`发行/` 不随源码仓库上传，首次下载仓库时没有这个目录是正常的。

1. 将刚生成的 ZIP 解压到一个新的本地目录。
2. 在能读写文件和执行命令的 Agent 客户端中，选择解压后的 `个人AI协作区` 文件夹作为工作区。
3. 请 Agent 按根 `AGENTS.md` 执行首次启用；也可在该工作区根手动运行 `py -3 -X utf8 中枢/工具/工作区管理/工作区管理.py init`。
4. 首次启用前说明默认普通自动记忆的范围；初始化得到空记忆、独立工作区标识和 `auto` 模式，不需再单独开启。不希望自动维护时使用相同管理命令加 `init --memory-mode manual`，启用后可用 `configure --memory-mode manual` 关闭。已有副本不因默认值变化而重置标识或模式。

自动维护只处理当前相关交流及已授权相关材料中有明确后续用途的普通记忆，不等于全盘扫描、每轮日志、保存凭据或敏感资料。`中枢/工具/工作区管理/工作区管理.py` 同时负责初始化、状态检查和模式配置；版本及出厂基线位于 `中枢/模板/`，两个运行 JSON 保持原位，不因整理而删除或重置。

若客户端未自动读取入口，使用模板内的相对路径启动指令。首版不安装客户端、插件或后台服务，不修改用户级配置，也不意味着所有客户端自动加载已验证。

## 系统演进怎样记录

管理体系的实质改动至少说明：

1. 目标、来源及原起点。
2. 实际变更对象与生效位置。
3. 验证证据、已知限制和未完成事项。
4. 与通用规则、工具或模板的对应关系；尚未提炼或同步时明确标记。
5. 必要的兼容与恢复注意事项。

设计、文件写入、实际加载、用户验收、通用化与发行分别报告。普通项目进展、每条记忆的日常维护和闲聊不自动变成系统升级记录。

## 个人化与能力边界

使用者可通过自己选择的规则、项目资料和有来源的普通记忆（包括个人偏好）逐步形成适合自己的工作方式；分发模板不包含预设 AI 人格或身份，也不表示训练或修改模型本身。不同模型与客户端的理解、工具能力和执行稳定性仍可能不同。

通用底座不能替新用户认领作者的偏好、AI 人格或操作授权。普通记忆用于保存有来源、有限定范围且可纠正的用户认识，不是 AI 人格设定。首次启用、记忆保存和敏感资料使用需要独立明确范围。

文件约定不是系统权限隔离。本地保存也不意味着交给远端模型处理时内容仍始终留在本地。

## 公开范围与许可证

本项目此前明确授权的源码更新范围为通用模板、工具、测试、设计及公开建设记录。每次源码改动、发布或应用到实际工作区都应按当次授权分别处理；本项目不会自动修改当前工作区或向外发送任何本地资料。

初始 `.gitignore` 采用明确纳入清单，未列入的顶级内容默认不跟踪；`本地/` 始终排除。添加新成果时先检查文件，再更新清单。忽略规则只减少误加入的机会，不能替代提交前审查，也不会移除已经被跟踪的秘密。

**许可证尚未选定。** 公开可读不等于已经授予任意复用、修改或再分发的许可；相关用途请先确认授权。
