# 2026-11-09：迁移、改名与大工作区检索纪律

## 背景与决策

用户希望将近期工作区调整和踩坑中可复用的经验纳入 `AI协作区建立与优化`，包括文件/主题迁移与改名，以及大工作区检索纪律。项目是结合用户实践经验与喜好、标准化建设可分发空白工作区的独立研发项目；本次只改研发项目和分发模板，不修改或迁移当前工作区。

决策：在模板现有《工作区维护指南》中补充通用流程，不复制用户工作区名称、机器路径、目录规模、项目名或平台专属命令；不实现专用迁移器或全盘扫描工具。

## 变更对象

- 大工作区检索：从路由和权威入口定点开始，按需要扩大范围；关注大型/生成/运行目录边界；核对分页、截断、退出状态及总量，避免将首屏或零命中误判为全局不存在；报告实际检查范围和未覆盖部分。
- 文件/主题迁移与改名：确认授权和真实源/目标，识别冲突和并发改动；变更前检索并分类引用，区分现行引用与历史证据；按风险建立适当基线；执行后修复并复查现行引用，核对目标与所选验证基线；仅在授权及核验成立时清理旧位置；需要时通过记忆 CLI 修复来源断链。明确迁移本身不扩大删除授权，也不等同模板升级。
- 版本从 `0.1.0-preview.4` 推进至 `0.1.0-preview.5`，同步发行清单与模板元数据。preview.4 的人格边界记录保留为历史，不回写。
- 新增模板发行合同测试，验证维护指南包含检索完整性、迁移引用分类和删除授权边界。
- README 中移除指向当前项目源码缺失的 2026-11-05 本项目记录的链接；不移除或修改当前工作区中的任何同名记录。

## 生效位置与边界

变更位于 `AI协作区建立与优化` 当前工作分支 `feat/template-no-personality-preview4`，preview.5 仍是仅供新建空白工作区的模板。已有 preview.4 或更早的工作区不能用复制新模板覆盖升级；需要迁移时应单独确认具体范围并遵循新指南。

未修改用户当前工作区；未生成发行包、未提交、未推送、未创建 Release，也未做全盘检索或处理平台运行目录。
