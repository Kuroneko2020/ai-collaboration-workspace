# 2026-11-09：一键升级命令

## 背景与决策

用户已把分发版模板在另一台设备上投入使用，希望升级与首次使用同样傻瓜：把新版 ZIP 放到任意位置，对运行在旧工作区的 AI 说"升级"即可。此前模板没有任何受支持升级路径（管理程序在版本不一致时拒绝并提示"需要显式迁移"）。

决策（用户确认方案）：`AI协作区建立与优化` 是独立研发项目，结合用户实践经验与喜好标准化建设可分发空白工作区；本次在发行包内新增升级脚本，由 AI 按包内规程驱动升级——人只负责放包和提出升级，字节级文件替换、备份、回滚与版本推进全部由脚本确定性完成，不交给模型临场发挥。本次只改研发项目与分发模板，不修改当前工作区。

## 变更对象

- 新增 `模板/个人AI协作区/中枢/工具/工作区管理/升级.py`，随每个发行包交付（发行清单 32→33 项）：
  - 校验链：目标工作区已初始化且含旧出厂清单；ZIP 逐文件与其内嵌出厂清单比对；以工作区旧出厂清单做三方分类（更新/新增/删除/冲突备份后采用新版/恢复缺失/保留本地修改）。
  - 绝不触碰启用状态、记忆配置、记忆条目、运行目录、记录目录、待整理目录与清单外内容。
  - 替换与删除先完整备份到 `升级备份/<时间戳>/` 并写 `报告.md`；提交前用新包 memlib 试载当前配置，不兼容即中止；提交后复核失败自动回滚；升级后尽力重建记忆派生索引。
  - 版本推进由脚本同步更新模板信息与启用状态（保留身份等字段），中断重跑幂等；同版本为无操作。
- 模板根 `AGENTS.md` 新增"收到新版发行包时的升级"节：AI 规程（解压到临时目录 → dry-run 审查 → 无冲突直接执行、有冲突或删除先经用户确认 → status 复核 → 汇报并保留备份）。
- 模板 README 的"不提供原地升级"段落改为上述傻瓜升级说明；`工作区管理.py` 版本不一致错误文案指向升级脚本；维护指南补一句受支持升级路径；中枢说明与路由文档同步。
- 项目层版本推进至 `0.1.0-preview.6`，同步发行清单、模板信息与各入口文档；preview.5 记录保持为历史。
- 测试新增升级端到端用例：真实包升级旧版工作区且记忆条目保留、dry-run 不落盘、幂等无操作、冲突备份后采用新版、上游删除与新增文件处理、拒绝未初始化工作区、拒绝被篡改 ZIP。
