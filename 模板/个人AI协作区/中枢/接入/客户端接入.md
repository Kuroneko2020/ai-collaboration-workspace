# 客户端接入

本模板通过普通文件提供共同入口，不绑定某个客户端或账户。首版面向 Windows 本地可写工作区、Python 3.11+ 和能够读写文件、执行命令的 Agent；不承诺其他平台或客户端自动加载。

## 一、最小接入方式

1. 将解压后包含根 `AGENTS.md`、`README.md`、`.gitignore`、`中枢/` 和 `待整理/` 的实际工作区设为客户端当前工作目录，不选择研发仓库或模板源码；工作区管理程序位于 `中枢/工具/工作区管理/工作区管理.py`，不在根目录保留脚本壳子。
2. 客户端如果确实支持读取根 AGENTS，让 Agent 按其中流程检查启用状态、读取灵魂与记忆入口。文件存在或客户端声称兼容，都不能代替实际读取证据。
3. 未自动读取时，将[会话启动指令.txt](会话启动指令.txt)粘贴进当前会话。它使用相对路径，不依赖作者路径；当前目录若不在实际工作区，先切换工作目录或使用客户端明确支持的文件选择方式，不猜目标。
4. 首次启用前按[根 README](../../README.md)与[根 AGENTS](../../AGENTS.md)告知默认普通自动记忆策略，用户选择采用后执行 `init` 即启用 auto，无需第二轮确认或额外 `configure auto`；首次可用 `init --memory-mode manual` 关闭，后续用 `configure` 切换。仅打开目录、读取文件或客户端接入本身不等于已经初始化，状态缺失、损坏或冲突时不写记忆，不用默认值绕过检查；缺 Python 时按根规则降级，不为模式选择阻塞普通任务。

共同权威文件始终在工作区中。Markdown 链接不是自动加载器，子级 AGENTS 也不保证被递归加载；执行具体事项时仍需显式按路径读取。平台自己的聊天、摘要、缓存或记忆不是共享文件的自动副本，不默认导入或双向同步。

## 二、首版不做的事

不安装 skills、MCP、hooks 或后台服务，不自动联网，不修改用户级或全局配置，不登录账户，不初始化 Git、提交、推送或外发。运行目录和平台配置不因接入而被扫描、搬迁或清空。

若用户以后明确要求持久客户端接入，应先确认该客户端实际支持的入口，再只合并范围限定的薄指引，保留原内容与可恢复备份；不得复制多套灵魂、记忆正文或作者路径。该操作属于新的明确授权任务，不由本模板预先执行。

## 三、如何核对接入

按事实分别记录，不用一个“已接入”覆盖不同层次：

| 层次 | 可接受的证据 |
| --- | --- |
| 文件存在 | 工作区入口与工具文件可定位 |
| 管理程序可用 | 在工作区根运行 `py -3 -X utf8 中枢/工具/工作区管理/工作区管理.py status` 的本机实际只读检查结果，模式与身份一致 |
| 客户端实际读取 | 在相应客户端的新会话中，观察到根 AGENTS、灵魂与记忆入口的真实读取 |
| 工具查询可用 | 在可写工作区成功执行适用查询；报告实际结果，不需为测试创建个人条目 |
| 背景被正确采用 | 回应遵守条目的范围、来源和有效条件；空记忆时不伪造背景 |
| 写入与后续检索 | 有明确保存请求或有效 auto 授权后，经 CLI 保存并在后续会话查得；不为验收绕过 manual |
| 用户使用验收 | 用户对实际体验的明确反馈，而不是文件或程序检查通过 |

模板本身不宣称任何客户端已达到以上层次。主会话的现有程序测试不替代用户本机的新会话验证；失败、跳过和未知应如实说明，不以改全局配置或安装依赖强行通过。

## 四、常见限制

- Agent 只能对话、不能读取文件或执行命令时：说明无法自动初始化或检索，由用户选择是否手工提供必要内容；不声称已完成接入。
- 缺 Python、无写权限、锁失败或工具错误时：按记忆入口人工降级，不直接手改公共条目。所有正常记忆查询也使用可写运行锁，不能在只读介质上以“查询不写内容”为由强行运行。
- 使用远端模型时：读取本地文件可能把内容交给相应服务。共享文件不是安全隔离，敏感资料仍需最小必要范围和合适的系统保护。
- 多客户端同时使用时：公共记忆通过同一 CLI 协调，遇到并发冲突停止争议性覆盖；锁只约束遵守协议的进程，不是任意编辑器的全局锁。
