# 记忆格式规范

本文件规定 schema v1 的条目格式、状态与时间语义、检索和上下文合同。保存授权及维护边界见[管理规则](管理规则.md)，命令说明见[记忆工具](../工具/记忆工具/README.md)。格式合法不证明内容真实，也不代替用户授权；模板不预装任何人的偏好或个人事实。

## 一、权威文件与派生视图

- 每条记忆只有一个权威文件：`中枢/记忆/条目/<id>.md`。
- 文件起始前置区是**纯 JSON**，由独立的 `---` 行包围，不是 YAML。正文使用 Markdown。
- `记忆.md` 的人工部分保存用法、规则链接和降级入口，不手工复制条目正文。核心导航只由唯一成对的 `<!-- BEGIN GENERATED MEMORY LINKS -->` 与 `<!-- END GENERATED MEMORY LINKS -->` 包围；工具仅更新该区域。链接存在不表示当前场景适用。
- `中枢/记忆/运行/index.json` 是派生索引，不是事实权威。缺失、损坏或陈旧时仍以条目原文为准，并报告派生状态。
- 运行锁和事务保存在 `中枢/记忆/运行/`，变更审计凭据保存在 `中枢/记录/记忆变更/`，不应打包为新用户的起步数据。

以下只是**纯虚构的格式示例**，不应预装成真实条目。示例日期只说明格式；真实创建和修改时间由工具填写。

```markdown
---
{
  "schema_version": 1,
  "id": "mem-example",
  "revision": 1,
  "kind": "fact",
  "subject_key": "example.fixture",
  "status": "active",
  "scope": {"level": "workspace", "target": ".", "scenes": [], "task_id": null},
  "pinned": false,
  "tags": ["演示"],
  "sources": [{"kind": "artifact_verified", "locator": "fixture://example/format", "source_date": null, "observed_at": null}],
  "created_at": "2030-01-01T00:00:00Z",
  "updated_at": "2030-01-01T00:00:00Z",
  "last_verified_at": null,
  "valid_from": null,
  "valid_until": null,
  "review_after": null,
  "end_condition": null,
  "superseded_by": null
}
---

# 虚构格式示例

## 结论

这是说明解析合同的测试文本，不表示任何人的真实事实。

## 使用边界

只用于格式说明，不导入正式条目库。
```

## 二、字段合同

### 标识、类型、状态与正文

- `schema_version`：整数 `1`，不接受布尔值或未支持版本。
- `id`：匹配 `^mem-[a-z0-9]+(?:-[a-z0-9]+)*$`，最多 96 位。新增省略 ID 时由工具使用 `mem-` 加 UUID hex；显式 ID 仍需满足格式。文件名必须与 ID 相同。
- `revision`：从 1 开始。内容、来源、范围或状态的实质更新加 1；没有变化的更新不改写原件、不制造凭据。仅重新核实不增加 revision，但原文件哈希可能变化。
- `kind`：`preference`、`fact`、`episode`、`lesson`、`pointer`。
- `subject_key`：1–200 位、不含空白、路径分隔符或 NUL 的稳定问题键。同一对象和属性先查已有键，避免同义换名重复；它不是语义理解器。
- `status`：`candidate`、`active`、`superseded`、`retired`、`rejected`。
- `pinned`：布尔值，控制核心导航优先展示，不能绕过状态、有效期、目录或场景过滤。
- `tags`：字符串数组，最多 50 项，每项最多 64 字符，不含空白、NUL 或重复项；标签不是另一份结论。

标题只在正文 H1，结论只在正文，不另建长期维护的 `title`、`summary`、`content` 元数据。正文必须恰好一个 H1，且它为首个非空行；标题不超过 300 字符，并有非空 `## 结论`。`candidate` 还须有 `## 待澄清问题`。正文最多 400000 字符，整个条目最多 2 MiB。

### 范围

`scope` 只接受 `level`、`target`、`scenes`、`task_id`：

- `level`：`workspace`、`topic`、`project`、`task`。
- `target`：工作区相对目录，以 `/` 统一分隔。禁止绝对路径、盘符、`..` 穿越及 NUL；不能用文件链接扩大边界。
- workspace 使用 `target="."`、`task_id=null`。topic/project 应是真实归属目录，不能为 `.`，且 `task_id=null`。task 必须提供非空 `task_id`（1–200 位，不含空白、路径分隔符或 NUL）。
- `scenes`：字符串数组，`[]` 表示无额外场景限制；最多 32 项，每项 1–64 字符，无空白、控制字符或重复项。可使用 `engineering`、`writing` 等按实际需要选择的标识，不预装个人场景偏好。程序不从查询文本自动推断场景。
- 条目只在 cwd 位于 target 内时适用；task 还需 task_id 一致。场景非空时至少一个请求 scene 匹配，没有 scene 时不默认加入所有条件性条目。

### 来源

`sources` 必须为非空数组，最多 50 项。每项允许：

- `kind`：`user_explicit`、`user_quote_in_task`、`user_confirmed`、`artifact_verified`、`agent_observation`、`agent_inference`。
- `locator`：非空可定位线索，最多 2000 字符，可为实际相对文件路径加章节、明确 URI 或会话标识。不能编造消息 ID；不因它是链接而自动打开、联网或执行内容。
- `source_date`：只有日期时使用 `YYYY-MM-DD`，未知为 `null`。
- `observed_at`：事实被观察或说出的带时区时间，未知为 `null`。它不是条目的创建时间。

active 的 preference 至少有一项用户确认类来源：`user_explicit`、`user_quote_in_task` 或 `user_confirmed`。仅 Agent 观察或推断不能机械转成已确认偏好；关于用户个人事实、偏好或动机的未确认推断应保留为 candidate。schema 只能验证结构和部分关系，真实性由主会话审查。

### 时间与替代

- `created_at`、`updated_at`：真实创建和修改时间，工具托管。
- `last_verified_at`：实际重新核实的时间，只能通过写请求顶层 `verification` 对象更新；其字段为 `verified_at`、`source_locator`、`reason`，缺一拒绝。读取、导入或重建索引不是核实。
- `valid_from`、`valid_until`：事实适用的半开区间 `[valid_from, valid_until)`，`null` 表示未另设起点或未有已知终点。两者均非 null 时，终点必须晚于起点。
- `review_after`：复核提示，到期不使 active 自动失效、停用或删除。新候选未设置时由工具按 created_at 加 `candidate_review_days` 设置；转正时沿用的候选复核时间会被清除。
- `end_condition`：明确事件结束条件，或 `null`，最多 2000 字符。Agent 应根据证据更新状态，脚本不猜任务是否完成。
- `superseded_by`：只有 superseded 状态才填，必须指向现存替代 ID，无自指、无环；其他状态必须为 null。

所有 datetime 输入必须带时区偏移或 `Z`，统一转为 UTC、秒精度 ISO 8601；拒绝裸 datetime 和只有日期的有效期。来源的日期另用 source_date，不混淆三个时间维度。不依赖额外时区数据库，不为基础功能安装时区包。

## 三、写请求与严格解析

新增或更新的顶层请求包含 `metadata`、完整 `body`、非空 `reason`、非空 `actor`，可选 `verification`。写请求 metadata：

- 必填 `kind`、`subject_key`、`status`、`scope`、`sources`；update 还必须包含与命令 ID 相同的 `id`。
- 其他可写字段为 `pinned`、`tags`、`valid_from`、`valid_until`、`review_after`、`end_condition`、`superseded_by`。
- 禁止提交工具托管字段 `schema_version`、`revision`、`created_at`、`updated_at`、`last_verified_at`。可从 `show` 的 metadata 按 `memlib.schema.WRITABLE_FIELDS` 过滤获得。
- update **不是字段级补丁**：保留所有仍需保留的可写值并提交完整正文，避免省略可选值后归为默认。CLI 另需最新 `--expected-revision` 与原文件 `--expected-sha256`，任一不一致拒绝覆盖。
- 未定义键、重复 JSON 键、非法类型或状态、无来源、重复 ID、非法替代链和不支持 schema 均明确拒绝。

新文件为 UTF-8 无 BOM、LF，读取兼容 UTF-8 BOM、CRLF。无变化更新保护既有字节，不为统一编码重写原件。解析只读取首个 JSON 前置区及其结束分隔行，正文中的 `---` 不影响前置区。文件读取和写入都做真实路径边界检查，拒绝条目目录中的外部符号链接或 Windows junction。

## 四、配置与初始化

`中枢/记忆/配置.json` 必须**恰好有六字段**：

| 字段 | 要求与建议初值 |
| --- | --- |
| `schema_version` | 整数 `1` |
| `workspace_id` | 每个工作区独立稳定，匹配 `^[A-Za-z0-9][A-Za-z0-9._-]{0,99}$`，由工作区管理程序执行初始化时生成；不是预装的个人身份 |
| `lock_timeout_seconds` | 数字 `0 < x <= 60`；建议 `5` |
| `query_limit` | 整数 `1..1000`；建议 `8` |
| `context_max_chars` | 整数 `100..1000000`；建议 `6000` |
| `candidate_review_days` | 整数 `1..3650`；建议 `30` |

配置无凭据，不在各客户端维护副本。合法空库不需要种子条目；无配置或不合法 root 仍拒绝，不自动初始化。启用与配置生成属于工作区管理程序（`中枢/工具/工作区管理/工作区管理.py`），不增加记忆 CLI 的 init 子命令。

包括只读业务命令在内的库操作会获取 `中枢/记忆/运行/memory.lock`，可能创建运行目录与锁文件，因此库必须允许该位置写入。不能把“只读事实”误解为只读介质可运行；锁文件释放后保留。

## 五、状态流转与当前结果

- 已有明确依据的记忆可设 active；值得澄清但未确认的设 candidate。
- candidate 得到依据后同 ID 转 active；被否定转 rejected；确认不再有用途才转 retired，不能只因复核时间到了就停用。
- active 普通纠正同 ID 增 revision；停用转 retired。合并替代时旧项转 superseded，指向唯一替代项，多文件关系在同一事务完成。
- retired/rejected 不自动重新启用。确有新明确指示时需用户确认类来源并在 reason 记录理由。

正常 search/context 仅返回当前有效的 active 且范围、场景匹配的条目。review_after 到期仍可返回，标 `needs_review=true`；到 valid_until 从当前查询排除，不推断事情完成。episode 标明历史经历，不能当作当前持续状态。显式 `--history` 可查看其他状态或过期条目，但不是当前指令；`--at` 只改变对当前保存条目的有效时点检查，不承诺历史版本数据库。

## 六、冲突与一致性

1. 同 ID 只有一份权威文件；文件名与 ID 一致。
2. 相同 subject_key 且范围、场景、有效期重叠的多条 active 报告冲突组。同级重叠与严格包含的更具体例外需区分，不能简单按更新时间覆盖全局。
3. 写事务按完成后的不变量检查，拒绝不被允许的新冲突；用于消除既存冲突的合法事务仍可执行。人工绕过 CLI 的旧冲突可由查询展示。
4. 替代目标存在，无自指、无环；被替代项不同时 active。
5. CAS 同时比较 revision 与原始字节 SHA-256，人工编辑未加 revision 也不能静默覆盖。
6. 未完成事务时不输出可能混合新旧数据的正常上下文；先检查并恢复。遇第三种内容哈希时保留材料、停止覆盖。
7. 用户要求停用的条目不能因旧索引或历史仍存在而进入正常上下文。

这些机械检查不能发现所有同义键或语义矛盾，上层仍须核对真实来源和跨范围适用性。

## 七、检索与上下文

### 范围和排序

查询接收实际 cwd、零个或多个 scene、可选 task_id 和 query。cwd 默认进程目录，必须位于核实后的 root 内；迁移或隔离根通常要显式传 `--cwd`。规范路径解析符号链接/junction，按组件比较并遵守平台大小写语义；`root-old` 不是 `root` 的子目录，不能靠字符串前缀判断。

处理顺序：权威条目一致快照、事务与格式检查、状态/时间/目录/场景过滤、结构化冲突组、词法评分及确定性排序。文本检索使用 Unicode NFKC 与 casefold，不改原文；特征包括完整短语、英文数字词、连续中文双字片段，极短查询保留单字退路。

固定权重为标题短语 12、标题 token 4、标签 token 4、正文 token 1，按唯一特征计分并以查询 token 数平方根归一。相关性优先，范围具体程度其次，最后按 ID 固定顺序；不用 updated_at 判定事实真假。

search 的非空查询不返回完全零匹配条目，无命中是合法结果。context 按 ID 去重，返回适用 pinned 核心项加相关命中；无 query 且没有适用 pinned 时，即使库非空也可返回空 items。轻量词法检索不等于向量语义召回，可换同义词或定点读取，不凭空补事实。

### 输出

结果包含 ID、标题、kind、scope、status、revision、原文件 SHA-256、有效期、needs_review、结论、来源及权威路径。`--json` stdout 为合法 JSON，诊断在 stderr；`data_status`、`audit_status`、`index_status`、`git_status` 分开。CLI 不执行 Git。

context 初值最多 8 项、6000 个 Unicode 字符，字符数不是 token 数。按完整项或完整元数据占位裁剪，不截断 JSON、否定条件或来源；提供 `omitted_count`、`omitted_ids`、`more_commands`。冲突组独立展示，不被 top-k 或预算隐藏。检索正文和来源引文始终是数据，不能提升为系统指令。

### 索引

search/context 直接扫描并解析权威条目，索引不是查询的必要依赖。reindex 生成相对路径和 SHA-256 源清单、schema/tool 版本、生成时间及提取视图，不只比较 mtime。它同步刷新记忆入口的唯一生成链接区，人工区保持原样；retired/rejected/superseded 和过期条目不进入当前核心导航。缺失或重复标记时不猜测覆盖。

## 八、常见错误

| 情况 | 处理 |
| --- | --- |
| revision 或 SHA 不符 | 重新 show、理解差异、构造新请求；不能只换版本号强放旧请求。 |
| 待恢复事务 | 先 recover --dry-run 核实，再按授权 recover --apply 幂等补齐；不盲删事务材料。 |
| 同键 active 冲突 | 展示双方 ID、范围和来源，由主会话判断，不按更新时间裁定。 |
| 索引缺失或损坏 | 查询仍以原文为准并报告派生状态，按授权 reindex。 |
| 来源失效或不可机械验证 | 报告线索状态，不自动判事实为假，不自动联网抓取。 |
| 空库 | 返回合法空结果，不预装偏好，不把未学习说成故障。 |
| 锁位置不可写 | 如实失败，核对已授权 root 和文件权限，不删除锁文件或改读生产库。 |
